# 可视化剧情与工作流设计

> 配套主文档：[完整设计方案](<../DESIGN.md>)。本文件定义产品领域模型与交互，不是可直接导入 n8n 的流程包。
>
> v1.1 增补：新手入口、点子卡、作者选择草稿与生成冻结契约。体验依据、研究协议与更完整的示例见[新手创作体验评审](<BEGINNER-AUTHORING-REVIEW.md>)；本文件只写领域契约，不重复其结论。

## 1. 两类画布，一套作品对象

| 维度 | 剧情画布 StoryGraph | 工作流画布 WorkflowGraph |
| --- | --- | --- |
| 回答 | 故事如何发生、如何讲述 | 工作如何执行、产物如何流转 |
| 节点 | 场景、事件、伏笔、转折、路线、注释 | 读取、检索、生成、检查、条件、人工审阅、提交 |
| 边 | 因果、先后、回收、视角、互斥路线 | 类型化输入输出、执行依赖、条件出口 |
| 环 | 关系图可有环；严格先后关系不可成环 | 顶层为 DAG；循环只允许显式有界容器 |
| 操作结果 | 改变剧情结构或可视布局 | 改变下一次执行的计划 |
| 主要产物 | 可编辑的大纲、场景卡和关系 | 候选稿、审校单、元素变化、版本提交 |

二者共享 `sceneId`、`entityId`、`projectRevisionId`，不用标题或画布坐标作为连接键。“在场景卡中添加角色”调用元素库创建/选择流程，获得稳定 ID 后再引用；不会在画布内部维护另一份人物资料。

## 2. 剧情画布

### 2.1 四种相互同步的视图

1. **大纲树**：作品 → 卷 → 章 → 场景。适合整理层级和导出顺序。
2. **场景看板**：草案、待写、初稿、修订、定稿；拖动列只改变创作状态。
3. **多线时间轴**：角色线/冲突线/伏笔线作泳道，可切换叙述顺序与故事内时间。
4. **自由情节图**：展示因果、铺垫、回收、交叉人物与备选路径。

视图改变同一组作品对象，不通过复制整套内容保持同步。布局、筛选、缩放保存为视图配置，不等于作品的语义修改。

### 2.2 场景卡字段

| 字段组 | 内容 |
| --- | --- |
| 身份 | 稳定 sceneId、标题、卷章、所属故事路线、创作状态 |
| 叙事 | POV、叙述人称、叙述时态、阅读顺序、故事时间/区间、回忆或梦境标记 |
| 冲突 | 场景目标、阻碍、选择、结果、情绪进入值/离开值 |
| 元素 | 实际在场者、仅被提及者、地点、关键物品、相关规则 |
| 状态 | 进入时前提、预期状态变化、允许揭示的秘密、禁止提前揭示的信息 |
| 文本 | 摘要、正文修订 ID、计划字数、实际字数 |
| 依赖 | 前置场景、伏笔、后续回收、关联工作流、待解决问题 |

允许只有标题的轻量卡片，其他字段逐步完善。运行某类任务时才校验其真正需要的字段。

轻量编辑实现以 `goal / conflict / summary` 承载目标、阻碍与预期结果／摘要，同时开放 `pov`（关联角色元素选择器）与 `storyTime`（故事时间）编辑，随现有场景 CAS 保存。行动、反应或对话是单次生成请求的写作意图，不是永久场景类型，也不另建一套场景卡。

### 2.3 类型化剧情边

| 边 | 含义 | 校验与展示 |
| --- | --- | --- |
| `narrative_next` | 阅读顺序 | 同一路线内生成可排序结构；与卷章顺序保持一致 |
| `happens_before` | 世界内先后 | 不得形成严格先后环；时间未知可保留偏序 |
| `causes` | 因果依赖 | 结果严格早于原因时提示核对；时间循环可用明确世界规则解释 |
| `sets_up` / `pays_off` | 铺垫与回收 | 未回收、重复回收和过早暴露可筛选 |
| `requires_state` | 场景成立前提 | 连接到元素属性/关系条件，不只连接人名 |
| `changes_state` | 计划中的变化 | 仅表示计划；正文采用并确认后才进入事实账本 |
| `alternative` | 互斥故事路线 | 每条路线有标识，检索不能混入其他路线事实 |
| `references` | 说明性关联 | 不引发执行，不必无环 |

“阅读顺序”是场景的业务属性；移动自由图中的节点位置只改变布局。拖动大纲树重排时则展示受影响章节、编号与状态查询，确认结构修改后提交。

### 2.4 AI 辅助画图与全周期局部情节推演

可用动作：根据构想生成大纲、把大纲拆成场景、补人物弧、分析因果缺口、列出伏笔回收建议、提出两个替代结局。

除开书阶段的交互式三步大纲外，故事画布与场景卡支持四类随处可用的局部情节推演（`plot_ideate`）及多便签孵化（`note_incubate`）：

1. **承接前场生成下一场（`next_scene`）**：基于指定场景已写正文或写作页“场景复盘”结论，生成 2–3 张不同走向的下一场计划卡，采用后经 `ChangeSet.sceneAdditions` 插入到该场景之后。
2. **两场戏之间的过渡桥接（`bridge_scenes`）**：选定前场 A 与后场 B，分析状态与因果缺口，生成 1–2 场过渡场景提案并插入中间。
3. **单场冲突与转折字段急救（`scene_brainstorm`）**：锁定场景卡中已确定的字段（如 `goal`），单独为缺失或卡壳的 `conflict` 或 `summary` 生成 3 个实质差异方案，采用后经场景 CAS 更新。
4. **章节一句话拆细纲（`chapter_breakdown`）**：将单章构想拆解为 2–4 场连续场景提案，支持逐场微调与子集采用。
5. **多便签 AI 孵化（`note_incubate`）**：勾选 1～5 条零散便签，整合孵化为串联场景卡、角色方案或世界观设定；采用后便签标记为 `linked`。

AI 返回 `StoryGraphPatch` 或 `SceneProposalCard[]`：新增/修改/归档哪些节点和边、引用哪些现有实体、理由与依赖。预览中新增用虚线、删除用删除标记；作者可局部采用。重复运行不复制同名场景：以稳定 ID 和基础图修订进行合并。

已有角色重名、新设定与旧设定冲突时，进入元素消歧和提案审阅；不会直接写成已确立事实。

### 2.5 点子卡与作者选择草稿

场景卡是作品里的稳定对象，点子卡是尚未采用的候选；两者不是同一个模型，也不共享字段必填规则。

| 对象 | 用途 | 是否进入作品版本 |
| --- | --- | --- |
| 点子卡 `IdeaCard` | 尚未采用的行动、动机、阻碍、结果与代价建议 | 否；采用后经 `StoryGraphPatch` 进入既有作品修订 |
| 场景卡 | 作品计划中一个场景的稳定对象 | 是；随作品修订提交 |
| 工作流节点 | 调用检索、Pi、审阅、提交等任务 | 否；属于流程定义与运行记录 |

点子卡可以对应场景的某个字段，也可以组合成多个场景；它不是执行节点，新手不需要理解端口、schema 或 DAG。

#### 2.5.1 点子卡字段与卡面

`IdeaCard` 引用字段以[运行架构](<ARCHITECTURE.md>) §6.2 为准。依赖和借用均指向 cardId + cardRevision，不追随可变标题或最新版本。卡面展示行动、阻碍、关注点和取舍，候选之间必须能用普通语言说明差异；只换形容词、场景颜色或人名不算实质差异。

卡面只表达三件事：**会发生什么**（一句具体行动）、**为什么值得选**（这条路关注什么关系、悬念或感受）、**选它要接受什么**（失去的机会、带来的麻烦或对节奏的影响）。可展开：暂定的新设定、依赖哪张卡、与已选内容的差异、一小段试演。不是每张卡都必须包含秘密、伏笔或反转。

#### 2.5.2 四种内容状态

```text
未采用点子：只在候选比较与组合任务中可见，不进入普通检索
选定计划：可供规划、场景目标与试演使用，明确标为“拟发生”
采用正文：当前稿件证据，可被检索；抽取出的事实仍可能待确认
已确认设定/事件：在对应时点、路线与修订中作为约束
```

选定计划不能冒充已经发生的事件，也不能因为“不是事实”就从写作上下文删除，否则无法按大纲写作。

#### 2.5.3 作者选择草稿与快照

`AuthoringDraft` 是宿主持久化的选择草稿，不是前端临时状态：`draftId` 标识草稿，`selectionVersion` 单调递增。每次选卡、改卡、锁定、借用、局部换或撤销都产生一个新快照，快照记录 `selectedCardRefs`（含 `cardId` 与 `cardRevision`）、`lockedDecisions`、`protectedSpans`、组合来源和撤销栈。撤销恢复历史快照与对应批次，不重新调用模型。

未采用点子不进入作品版本。作者把点子放入计划时生成既有 `StoryGraphPatch`，经作者审阅后随 `ChangeSet` 纳入**既有作品修订**；本方案不新增“计划版本树”，计划的演进体现为作品修订与场景卡字段的变化。

#### 2.5.4 片段示例：一张未取鞋的收据

已给输入只有一句虚构点子：一个准备关掉父亲旧修鞋铺的年轻人，发现一张十年前未取鞋的收据。完整示例见[新手创作体验评审](<BEGINNER-AUTHORING-REVIEW.md>) 第 6 节。

点子卡（均为可选建议，不替作者确立背景）：

| 卡片 | 行动与阻力 | 值得选什么 | 代价 |
| --- | --- | --- | --- |
| A 把鞋送回去 | 关铺前寻找取鞋人，联系方法已经过时 | 一次拜访、人与旧物的关系 | 要为一件可能无人需要的事花时间 |
| B 把这笔账问清 | 向父亲追问为何一直留着这一单 | 一场具体的父子对话 | 必须面对两人对关店的不同期待 |
| C 做完最后一单 | 关店前修好这双旧鞋 | 手艺、失败与完成一件事 | 未必保住店，也未必被感谢 |

作者可以选 A，同时借用 B 的“父亲不赞成寻找顾客”，并明确接受“父亲健在”这一新增建议。系统只补当前缺的一步——“什么让他真的出门”，给出三个小项供分别保留、改写或舍弃，而不是拼接整份大纲。选定后形成一条可预览的因果链，其中“仍会关店”保持锁定；未确定的环节允许留空，系统不因缺环自动补上父亲去世、身份反转或大团圆。

## 3. 工作流画布交互

### 3.1 页面分区

- 顶部：名称、编辑版本、运行版本、校验、试运行、运行、停止后续、历史。
- 左侧：可搜索节点库和模板；不把所有 CLI 命令摊成节点。
- 中间：节点与端口、缩放、框选、对齐、缩略地图、折叠组。
- 右侧：配置表单、输入字段映射、输出类型、权限、预算、引用对象。
- 底部：执行时间线、节点输入输出、证据、事件、失败原因。

节点内只展示名称、作用对象、状态和关键信息；输入全文与模型参数按需展开。

### 3.2 连接与配置

- 端口有类型和数量：单值、列表、可选值；不可兼容的连线即时说明原因。
- 输入映射优先用“选择上游输出字段”，高级表达式仅支持白名单字段访问和纯函数，不执行任意 JavaScript 或 Shell。
- 拖线到空白处弹出兼容节点推荐；键盘用户可通过“连接到”表单完成同一动作。
- 右侧表单同时显示静态示例与最近一次真实输出，示例必须带“测试数据”标签。
- 点击“运行到此处”先预览会触发哪些上游任务和预计消耗，不能暗中重跑整个作品。
- AI 可生成工作流草案，也可建议插入检查节点；导入后必须经过同样的静态校验。

### 3.3 作者日常入口

新手从起步三入口进入短卡或直接写作；已有计划的作者可选场景运行模板。二者共用相同对象和执行器，需要定制时才“打开流程”，不要求先学会编排。

### 3.4 新手入口与点子卡操作

新手默认入口是可跳过的创作起步页，不是逐字段问卷或空白流程画布。三条路径互不为前置，任何一条都能到达第一场戏：

| 入口 | 适用 | 之后发生什么 |
| --- | --- | --- |
| 帮我找个开头 | 只有兴趣或一个画面 | 生成少量短点子卡，也可先浏览示例故事 |
| 我有一个点子 | 已有一句话或一个念头 | 保留这句话的核心，只补当前缺的一步 |
| 我直接写 | 想从正文、对白或粘贴片段开始 | 编辑器直接可用，之后可反向整理场景卡 |

不要求先填题材、POV、目标字数或全部场景卡字段，不要求先连接全部 CLI，不设教程关卡或必答问卷。已有语音输入可作为文本输入方式，不为降低门槛新增独立语音引擎。首屏文案与路径说明见[新手创作体验评审](<BEGINNER-AUTHORING-REVIEW.md>) 第 4 节。

#### 3.4.1 点子卡必备操作（P0）

| 操作 | 行为 |
| --- | --- |
| 保留这一点 | 锁定一个创作决定，不锁死措辞 |
| 只换这里 | 以其余已选内容为约束生成新候选，旧批次仍可找回 |
| 借这个点子 | 从另一张卡取一个动机、阻碍或场面，预览组合影响 |
| 看看写出来怎样 | 生成可丢弃试演，标为候选，不写入正稿 |
| 我来改 / 加一张 | 自写卡与 AI 卡同权，未填字段保持未知 |
| 这次不想要 | 只影响当前批次；可另存为本书偏好 |
| 撤销 / 回到上一组 | 恢复选择与组合，保留历史产物，不重复计费生成 |

“保留含义”与“保护原句”是两个独立开关：前者防止剧情决定被改写，后者保护特定文字不被改写。默认不预选“最佳卡”，也不显示采用数量给作者施压。锁、换、借、撤销属于 P0，不得因实现顺序而后排到体验验证之后。

候选数量、试演长度与首场戏完成时间都是**待测可调参数**，不是已验证的最佳值；测量协议见[新手创作体验评审](<BEGINNER-AUTHORING-REVIEW.md>) 第 12 节。

#### 3.4.2 试演与改写范围

试演按需展开，不自动批量生成多篇长文供比较。试演产物标记为候选，可丢弃，不进入正稿与作品修订。

写作与推敲提供两个可见模式：**只改表达**保留已确认事实、场景目标和保护项；**允许扩写**可提出动作、细节与过渡。关键死亡、身份、归属或新角色等变化列为新增剧情提案，可在聚合审阅中一并决定，不能隐含在语言修改中；普通动作质感不逐字弹窗。推敲按作者目标一次呈现一处观察，复用语言编辑职责，不新增永久 Agent。

#### 3.4.3 三级提示

| 级别 | 含义 | 处理 |
| --- | --- | --- |
| 冲突 | 已确认约束互斥，证据充分 | 合入前解决，或修改旧设定、另存备选路线 |
| 因果缺口 | 决定与后果之间缺少可识别连接，或所需信息缺失 | 提示缺口，允许暂缺；不把未知判为错误 |
| 审美建议 | 节奏、重复、表现手段等主观判断 | 可选提醒，作者可以认为重复具有意义 |

`unknown` 不判错：因果缺口可以是留白，也可以由作者补上。因果连接由作者确认，不以模型评分代替。

## 4. 核心节点库

以下是平台业务节点；其内部可能调用 CLI、检索服务或事务，不代表 n8n 原生节点。

| 类型 | 输入 → 输出 | 关键行为 |
| --- | --- | --- |
| 选择作品/场景 | 用户选择 → `SceneRef` / `SceneRef[]` | 冻结目标对象和基础版本 |
| 生成点子 | 创作输入、已有计划 → `ProposalBatch` | 生成少量短点子卡，每卡给出行动、值得选的理由与代价；差异须实质；方向未定前不批量生成整卷正文 |
| 记录选择 | `IdeaCard` 引用、锁定与借用 → `AuthoringDraft` 快照 | 选卡、改卡、锁定、借用、撤销产生新 `selectionVersion`；持久化在宿主，不依赖前端状态 |
| 读取元素状态 | `SceneRef` → `WorldState` | 按故事时点、路线、作品修订查询 |
| 检索上下文 | 场景、状态、问题 → `ContextBundle` | 混合检索，附来源、排除项与预算；普通召回排除未采用候选，选定计划以“拟发生”进入上下文 |
| 生成内容 | 上下文、任务 → `DraftArtifact` / `OutlineProposal` | 选择角色与 Agent 配置，返回候选；按“只改表达 / 允许扩写”限定范围，关键新事实转新增剧情提案 |
| 试演 | 点子卡或选区、意图 → `DraftArtifact`（试演） | 可丢弃候选，不写入正稿与作品修订；长度与数量为可配参数 |
| 抽取变化 | 候选/已采用文本 → `FactProposal[]` | 候选阶段可预抽取用于检查和预览，不能写成事实；对实际采用范围重新核对，计划仍标拟发生 |
| 一致性检查 | 文本、状态、变化 → `IssueReport` | 规则检查 + 证据检索 + 语义评估；输出分冲突、因果缺口、审美建议三级，`unknown` 不判错 |
| 条件分流 | 类型化字段 → 互斥分支 | 如存在已证实的阻断问题；支持 unknown 出口 |
| 遍历场景 | `SceneRef[]` → 每项子流程结果 | 有限列表、明确并发与失败策略 |
| 人工决定 | 候选/问题/变更 → `DecisionRecord` | 选择、修改、拒绝、退回；持久化等待 |
| 形成修订包 | 文本、事实提案、选择 → `ChangeSet` | 计算依赖；部分采用后重新核对事实 |
| 提交修订 | 已审 `ChangeSet` → `RevisionRef` | 基础版本校验、幂等、原子提交 |
| 汇总/导出 | 结果或版本 → `ReportArtifact` / `ExportArtifact` | 失败摘要不能包装成完整成果 |

增强节点：多候选比较、可复用子流程、网络资料查询、外部 webhook。自定义命令节点不作为首版通用出口，以免绕开连接配置与作品数据边界。

### 4.1 节点共同配置

`id`、`type`、`typeVersion`、输入输出 schema、参数、运行策略、重试策略、超时、权限配置引用、预算、产物类型。

画布坐标、折叠状态和节点颜色置于 `ui`，不参与执行语义哈希。密钥、绝对凭据路径和用户目录不写入可分享模板。

### 4.2 端口数据不是聊天记录

- `SceneRef`：作品、分支、路线、场景、基础修订。
- `WorldState`：时点快照、适用规则、已知/未知/冲突状态、角色知识范围。
- `ContextBundle`：确切引用、检索快照、选中段落、角色可知信息、创作约束；区分已发生事实与标为“拟发生”的选定计划。
- `DraftArtifact`：独立候选内容、结构、生成来源及完整性状态；试演候选额外标记为可丢弃。
- `IssueReport`：问题、严重度、证据和可判定程度；等级区分冲突、因果缺口与审美建议。
- `ChangeSet`：预期基础版本、文本/事实/图修改、采用范围与审阅记录。
- `IdeaCard`：未采用的行动、动机、阻碍、结果与代价建议，带 `cardId`、`cardRevision`、批次与来源引用。
- `ProposalBatch`：不可变的点子卡批次，含批次内候选、来源任务与生成冻结引用。
- `AuthoringDraft`：作者的选择草稿与不可变快照，含 `draftId`、`selectionVersion`、已选卡引用、锁定决定、保护片段与撤销栈。

传递 ID 与内容哈希并按权限读取大产物，避免长篇文本在每条连线上复制。

## 5. 执行语义

工作流运行器是 Pi 之上的领域调度层。生成、抽取和语义审校默认提交到 Pi RPC；状态查询、检索、差异和数据库提交由领域服务完成。模型选择、工具循环、会话压缩沿用 Pi。流程画布不是第二套模型调用框架。

### 5.1 定义、版本与运行

```text
编辑草稿 → 校验 → 保存不可变 WorkflowVersion → 创建 Run
                                      ├─ 冻结作品与上下文快照
                                      ├─ 创建各 NodeRun
                                      └─ 持久化事件与产物
```

Run 固定工作流版本。运行中修改画布只影响以后新运行。读节点默认读取冻结的作品快照；若“提交修订”产生新版本，下游仅在显式连入该 `RevisionRef` 时读取新版本。

### 5.2 状态

Run 状态：`queued → running → succeeded / failed / cancelled`，并支持 `waiting_human`、`paused`、`cancelling`、`interrupted`。

NodeRun 状态：`pending → ready → running → succeeded`，分支状态另有 `waiting_human`、`failed`、`skipped`、`cancelled`、`interrupted`、`blocked`。

- 仍有可执行节点时 Run 保持 `running`，同时显示待人工事项数；没有可执行工作而仅等待人类时为 `waiting_human`。
- `paused` 表示调度器不再启动下一节点，不表示已经挂起 CLI 或供应商推理。
- 暂停请求在当前节点安全结束后生效；立刻停止当前生成使用取消。
- 被跳过的条件支路为 `skipped`，不判失败；依赖失败的节点为 `blocked`。
- 必需产物完整且所有必需节点满足成功条件，Run 才成功。

Pi `prompt` 的成功响应只表示接收、排队或被扩展处理；`agent_end` 也不是整项任务完成。需要等待当前 Pi 操作的 `agent_settled`，再核验产物和终止原因；`disposition=handled` 未启动运行时不能无限等待该事件。领域 Run 成功与 Pi 就绪是不同层级。

### 5.3 条件、合流和循环

- 条件节点产生单一选中出口；对不确定事实提供 `unknown` 路径，不能将 unknown 当 false。
- 普通合流等待当前路径选中的所有必需输入，不等待被条件跳过的支路。
- 多候选并行时显式设“等待全部”或“达到指定数量”；不允许任意竞速覆盖结果。
- 循环仅提供受控遍历和返修容器；配置最大项数、最大迭代、总预算、超时与停止条件。顶层图不允许任意回边。
- 相邻正文依赖前一场景状态时串行，独立审校可并行。
- 返修上限建议默认 2 次；达到上限交作者决定。

### 5.4 人工节点

人工节点持久化：待办 ID、提问、候选、输入哈希、作品基础版本、选项、必要说明。答案形成不可变记录。

等待期间输入已变：展示差异，先确认沿用还是重新计算；原确认不能自动适用于新候选。预算/工具权限变化时同样失效。

创作确认与工具授权不是同一份令牌。“同意这个剧情”不等于允许 CLI 执行任意程序。

Pi 的 `extension_ui_request` 适合即时选择、确认、输入；持久化创作关卡由宿主保存任务后释放当前生成阶段，再根据决定启动下一阶段。进程重启后无法向旧 Pi 请求 ID 重放一个过期回答。RPC 不支持的 TUI 自定义组件使用平台表单替代。

### 5.5 重试、局部重跑和缓存

- 平台与 CLI 内部重试共同记入尝试记录，避免两层重试放大。
- 可重试网络错误有限退避；鉴权失败、参数错误、预算耗尽不自动重试。
- 数据库提交以幂等键去重；外部模型调用不承诺 exactly-once。
- 已发出但结果未知的调用标为 `interrupted`，核对已有 session/产物后决定，不能假定未执行。
- 从节点重跑创建新 attempt，旧结果保留；其下游结果失效，先展示受影响范围。
- 缓存键含节点语义、输入哈希、模型/适配器、模板版本、上下文快照和规则版本。
- 确定性读取/转换可缓存；生成仅在作者选择“复用这次输出”时复用。“再来一稿”创建新采样。
- mock/固定样例试运行不能连接真实提交或发布节点；真实模型试运行明确显示成本。

### 5.6 恢复和取消

- 节点完成先记录产物，再以事务完成状态转移和下游调度登记。
- 重启后已成功节点不重跑，人工待办恢复；运行中的调用先与宿主和协议状态对账。
- 取消先停止下游调度，再请求协议中断，最后由进程管理器清理本任务进程树。
- Pi 取消整项任务先发送 `clear_queue`，再发送 `abort`，因为遗留的 steer/follow-up 消息可能使 Pi 继续执行。正常的“补充要求”与“完成后继续”分别映射到 Pi 对应队列，不能混作立即中断。
- 取消后保留部分结果并标记不完整；迟到事件不使任务重新变成功。
- 本地进程退出不等于远程模型立即停止计费；界面区分本地终态与供应商账单状态。

### 5.7 生成冻结与哈希核对

涉及点子草稿的生成请求冻结以下引用；未使用卡片的纯正文任务可省略草稿字段，仍冻结正文基础版本、意图与上下文，规则以[运行架构](<ARCHITECTURE.md>) §6.5 为准：

```text
baseRevisionId      作品版本（当前 project revision）
basePlanHash        计划投影哈希（选定计划与相关剧情对象的摘要）
draftId             作者选择草稿
selectionVersion    选择快照版本
selectionHash       当前选择内容哈希
intentHash          作者意图（本次要解决什么）哈希
contextSnapshotId   上下文快照
```

规则：

- 新请求使用新的 `generationRequestId` 与 `attemptId`；网络重试沿用同一 `idempotencyKey`，不产生第二个 attempt。
- `reuseOfArtifactId` 只在作者显式选择“复用这次输出”时出现；它与“再来一稿”（新采样）分别记录，不混为一谈。
- 任务返回或产物被采用之前，比对冻结的版本与哈希。当前 `baseRevisionId`、`selectionVersion` 或任一哈希不一致时，结果只归档为过时候选，不替换当前选择、不覆盖计划。
- 比较任务必须显式引用候选的 `cardId` 与 `cardRevision`；未采用的候选不进入普通检索召回。
- 迟到结果与未采用的旧批次保留可查，不因“看起来更好”被自动采用。

对比较/组合等消费已有卡片的节点，输入键还含批次及明确的卡片版本集合；新生成的输出批次 ID 不参与生成前的缓存键。新尝试与显式复用规则以[运行架构](<ARCHITECTURE.md>) §6.5 为准。

## 6. 六套原创领域模板

以下为本方案的原创结构定义，不复制商业模板文案。实施时映射为平台 schema。

### T01：从一句点子到可写大纲

新手路径（默认）：

```text
创作输入（可空） → 生成少量点子卡（ProposalBatch）
                 → 作者选 / 锁 / 借 / 局部换（AuthoringDraft 快照）
                 → 按需试演 → 补当前缺的一步
                 → 形成场景计划（StoryGraphPatch 预览）→ 作者采用 → 提交既有作品修订
```

输入：一句点子、一个画面或已有设定均可；题材、篇幅、POV 可以留空，篇幅目标不是必填项。产物：点子卡批次、作者选择草稿快照、场景计划补丁与新元素提案。初次只补当前缺的一步，不要求先规划全书；进阶作者仍可直接构建卷章大纲。

方向未定前不批量生成整卷正文。已选点子通过 `StoryGraphPatch` 进入既有剧情对象，随作品修订提交，不建立独立的“计划版本树”。

### T02：一个场景的创作

```text
选择场景（或由点子卡形成） → 读取状态与已选计划 → 按用途检索
         → 明确本次范围 → 生成候选 / 作者写作 → 预抽取变化与一致性检查
         → 可选推敲一处 → 作者选择采用范围 → 核对实际采用文本与事实提案
         → 聚合审阅修订包 → 提交版本（或先保存正文、知识待整理）
```

写作助手获得受控信息；规划约束与角色可知素材分区，计划标为“拟发生”。已确认且未变化的场景目标不重复询问，正文检索排除未采用方案。有矛盾时可退回受控返修，不自动修改世界规则。

可选的“推敲一处”是 T02 的一个环节，不是独立节点，也不新增独立审校 Agent：一次只提出一处可定位的问题，作者可以全部保留、跳过或结束本轮。

### T03：全卷逻辑巡检

```text
冻结本卷版本 → 遍历场景 → 还原各场景状态 → 检查事实/知识/物品/时间
             → 合并重复问题 → 按严重度与因果链分组 → 作者处理问题单
```

不自动改正文；报告区分已证实矛盾、可能矛盾、缺少证据。修复是单独变更集。

### T04：早期设定变更与联动修订

```text
选择旧事实 → 提出新事实 → 查询引用/事件/剧情依赖 + 语义补充检索
           → 作者选影响范围 → 建立修订分支 → 生成局部修复候选
           → 检查新旧时间线 → 联合审阅 → 选择性合并
```

每个下游修改显示“为什么受影响”，原主稿仍可继续写作。

### T05：两个结局对比

```text
冻结分叉点 → 建立路线 A / B → 分别读取路线状态 → 生成结局提案
           → 分别检查伏笔/动机/代价 → 同屏对比 → 作者选择或继续探索
```

两条路线的 RAG 隔离；比较步骤可同时读取，混合上下文不得用于单一路线创作。

### T06：导入旧稿并建立元素账本

```text
导入预览 → 确认章节与场景 → 分段抽取元素/别名/关系/事件
         → 同名消歧 → 对齐时间与证据 → 作者批量确认
         → 提交初始知识版本 → 建立关键词与语义索引 → 抽样问答验证
```

未确认事实保留为候选；未知时间不按章节号伪造日期。失败可从最后完成的场景继续。

## 8. 版本与差异

剧情图差异显示场景新增/归档、顺序、因果、时间和路线变化。工作流差异显示节点类型、配置、连接、权限和预算变化。纯布局差异可隐藏。

模板升级以旧模板、新模板、当前流程做三方对比，不覆盖作者修改。模板不携带凭据；外部程序、网络目标、输入输出路径需重新绑定。

流程版本与执行记录分离，参考 [n8n 对两种历史的区分](<https://docs.n8n.io/workflows/history/>)；画布组件参考 [React Flow](<https://reactflow.dev/learn>)，恢复与执行语义由本平台实现。

## 9. 专项验收

1. 连接 `IssueReport` 到只接受 `SceneRef` 的端口，阻止并说明缺少转换。
2. 顶层循环使运行校验失败，有界遍历可执行。
3. 未选支路跳过，合流不死等。
4. 人工等待跨应用重启恢复；修改输入后旧答案不被复用。
5. 生成重试保留旧候选，提交重复投递只产生一个修订。
6. Agent、模板或知识版本改变，旧缓存不能冒充新结果。
7. 移动节点、变更缩放不影响语义哈希和正文版本。
8. 场景 A 改变场景 B 的进入状态，B 不得无提示沿用旧快照。
9. 取消时运行节点、待批准请求和后续任务都得到正确终态。
10. 测试数据和真实任务明确区分，固定样例不会正式提交。
11. 导入未知节点模板可展示问题，执行器拒绝运行。
12. 列表模式可完成添加、连接、配置和运行，功能不依赖拖拽。

### 9.1 新手入口与点子卡

13. 未填题材、POV、目标字数或全部场景卡字段时，仍可从示例、点子卡或直接写进入创作。
14. 点子卡给出行动、值得选的理由与代价；与同批候选只有措辞差异时不算实质差异。
15. 选卡、改卡、锁定、借用与撤销都产生新的 `selectionVersion` 快照；重启应用后选择仍在。
16. 撤销换卡后能找回旧批次候选与原选择，且不重复发起模型调用。
17. 借用另一张卡的一项并同时手改时，迟到结果标为过时并可比较，不覆盖当前选择。
18. 试演引入关键新事实时转为新增剧情提案，不随语言修改直接提交。
19. 一致性检查输出区分冲突、因果缺口与审美建议；`unknown` 不判为错误。
