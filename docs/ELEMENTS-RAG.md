# 元素数据库、时态记忆与 RAG 设计

> v1.1 设计基线 · 主文档：[完整设计方案](<../DESIGN.md>) · 联动：[剧情与工作流](<CANVAS-WORKFLOW.md>) · 存储与接口：[技术架构](<ARCHITECTURE.md>)

## 1. 核心原则：检索库不是事实库

长篇一致性需要四层，而不只是“把全书切块放进向量数据库”：

```text
原文与设定证据
  ↓ 引用、抽取、确认
结构化元素 + 事实/关系 + 状态变化事件
  ↓ 按作品版本、故事路线、时点、知情者还原
可查询的世界状态与人物知识状态
  ↓ 结构化约束 + 关键词 + 语义召回
生成上下文 → 候选正文 → 再次抽取与检查 → 作者采用
```

- **权威层**保存作者确认的内容、设定、事件和修订关系。
- **检索层**保存可重建索引，帮助找到证据，不拥有决定事实的权力。
- **检查层**用规则与模型识别矛盾；未知、推测和已证实问题分开呈现。
- **审阅层**决定新事实是否成立，或是否需要修改旧稿、补过渡事件。
- **材料按来源分层**：候选、选定计划、采用正文、作者直接设定，对应 `candidate` / `selected_plan` / `manuscript` / `author_setting`。来源不等于真值；断言另有语义、审阅状态、有效时点与知识视角。契约见[技术架构](<ARCHITECTURE.md>) 第 6 章。

本方案借鉴 [Novelcrafter Progressions](<https://www.novelcrafter.com/help/docs/codex/progressions-additions>) 按场景呈现设定变化的机制，进一步显式建模故事时间、角色知识、修订分支和证据状态。

## 2. 元素类型与属性

### 2.1 内置与自定义类型

| 类型 | 示例属性 | 典型关系 |
| --- | --- | --- |
| 角色 | 姓名、别名、年龄、外貌、身份、目标、伤势、能力、知识 | 亲属、敌友、隶属、知晓、携带、位于 |
| 物品 | 唯一性、数量、材质、用途、状态、剩余次数 | 所有者、持有者、存放地、组成、开启对象 |
| 地点 | 地理层级、通行条件、距离、环境、开放状态 | 包含、邻接、可达、隶属 |
| 组织 | 目标、制度、成员、资源、存续状态 | 成员、盟友、敌对、控制地点 |
| 能力/技能 | 条件、代价、范围、限制、冷却、学习阶段 | 掌握者、克制、依赖物品 |
| 规则/制度 | 适用范围、约束、例外、生效时段 | 约束元素、允许事件、冲突规则 |
| 事件 | 参与者、时点、地点、原因、结果 | 前置事件、影响元素、被提及场景 |
| 线索/秘密/伏笔 | 内容、真假、埋设、揭示、回收状态 | 知情者、误解者、证据、回收场景 |
| 自定义 | 如势力等级、货币、科技、血统、任务 | 使用可配置属性与关系定义 |

“记录使用过的元素”包含实际出场、仅被提及、回忆、计划引入四种情况。它们不是同一种关系；提到一个角色不意味着该角色当时在场。

### 2.2 属性类型

提供文本、枚举、布尔、整数、定点数、数量与单位、时间/区间、实体引用、实体列表及受约束结构字段。

- 未知、明确不存在、不适用、具体值是不同状态；未知剩余次数不是 0。
- 数量必须有单位；“三枚金币”和“三袋金币”不能直接相减。
- 年龄优先由出生信息和故事时间计算；日期不精确时返回区间，不编造精确年龄。
- 不强制所有小说数值化。感情、忠诚、动机可以是带证据的描述与变化，不伪装成客观分数。
- 自定义字段定义及其类型迁移有版本；不能静默把旧整数改为文本并破坏约束。

### 2.3 身份和别名

元素使用稳定 ID。姓名、化名、称号是 `Alias`，可有有效时期、语言和知情范围。

实体解析先精确匹配/别名匹配，再给语义候选；同名角色、同类物品、复制品、伪装身份都须可区分。合并实体前展示来源和被引用范围，支持撤销合并。人物更名不改变其 ID。

## 3. 不能混为一谈的几个坐标

| 坐标 | 含义 | 示例 |
| --- | --- | --- |
| 作品修订 | 作者在何次修改后认可这份内容 | 初稿 r12 / 修订稿 r18 |
| 修订分支 | 在哪一种创作方案中 | 主稿 / 更换凶手方案 |
| 故事路线 | 同一方案内哪条情节路径 | 留城 / 出海 |
| 故事时间 | 虚构世界中何时成立 | 雾历四年第三日清晨 |
| 叙述顺序 | 读者何时读到 | 第八章的一段倒叙 |
| 记录时间 | 平台何时保存这项知识 | 某次人工确认时间 |
| 知识视角 | 谁认为或知道什么 | 林雾以为钥匙仍在沈砚处 |

这相当于**版本化的双时态事实 + 叙事可见性**：世界内生效时间与数据库记录时间分开，阅读顺序另存。

首版支持精确时间、时间区间、相对先后和场景锚点。自定义历法使用 `calendarId`；不同历法未定义换算时不强行比较。未知时间只保留偏序，不能把章节编号当日期。

### 3.1 修订分支与故事路线

分支通过不可变作品清单继承共同祖先中的内容和事实，发生修改时覆盖对应引用；不是查询 `revision <= 当前版本号`。合并版本可能有多个父节点，版本 ID 也不代表线性时间。

故事路线单独存储进入条件和继承范围。当前路线只读取可达且已选中的事实；比较路线的工具有单独权限，比较结果不能直接作为某一路线的写作上下文。

## 4. 领域数据模型

| 对象 | 关键字段 | 职责 |
| --- | --- | --- |
| `Entity` | id、typeId、创建来源 | 稳定身份，不直接存唯一的“最新状态” |
| `EntityType` / `PropertyDefinition` | schemaVersion、数据类型、约束 | 定义字段与可迁移规则 |
| `Alias` | entityId、名称、有效范围 | 消歧和提及匹配 |
| `FactAssertion` | subject、predicate、typedValue/object、语义类型、状态、`sourceKind` | 表达属性和关系断言 |
| `StateEvent` | 时间、前提、effects、参与者、规则版本 | 描述转交、受伤、消耗、获知等变化 |
| `Evidence` | 源修订、sceneId、blockId、原文范围、hash、`sourceKind` | 证据定位与失效判断 |
| `KnowledgeAssertion` | holderId、内容、belief/known、来源、获知/遗忘事件 | 表达人和读者的信息状态 |
| `Mention` | entityId、sceneId、类型、文本锚点 | 区分出场、提及、回忆和计划 |
| `WorldStateProjection` | 作品清单、路线、故事时点、规则版本 | 可重建的状态投影 |
| `Issue` | 类型、严重度、证据、检查覆盖、处理状态 | 一致性问题闭环 |
| `ContextSnapshot` | 输入修订、检索策略、选中证据、模型配置 | 记录某次生成实际看到了什么 |

事实、关系和事件保存在 SQLite 权威表中。关系图由这些表生成；首版不需要另建图数据库作为第二事实源。

### 4.1 一条断言不等于一个真相

每条断言具有：

- 语义：`world_fact`、`belief`、`rumor`、`deception`、`plan`、`hypothesis`。
- 审阅状态：候选、已确认、已拒绝；已确认断言被新版本替代时保留旧引用。
- 证据：原文、作者直接设定或导入资料，不能只有模型生成的总结。
- 来源种类：`candidate` / `selected_plan` / `manuscript` / `author_setting`。`selected_plan` 表达拟发生，不得当作已发生证据；作者直接手写确认的设定是合法来源，可无正文锚点，沿用 5.2 的作者设定入口标注。
- 来源可信性与抽取置信度：分别记录，不把模型自报 0.99 当成作者确认。
- 有效范围：作品修订清单、路线、世界时间区间、可见主体。

两个角色持相反看法不是数据库冲突。只有两条适用范围重叠、均表达世界事实且互斥的断言，才进入真正的事实冲突检查。

### 4.2 属性和关系变化

稳定描述用事实断言；发生变化的属性/关系用事件衔接。有效区间采用半开区间 `[from, to)`，未知边界显式表示。

“钥匙转交”是一个原子事件：验证旧持有者 → 结束旧持有关系 → 建立新持有关系 → 更新携带位置投影。所有权、持有权和所在地分开，借用不自动转移所有权。

同一时点有多个互斥事件而缺少先后关系时，返回“顺序不明”，不能按数据库插入顺序任意挑一个。

### 4.3 结构示例

以下为虚构作品中的字段示意，不是已存在的数据库记录。

```json
{
  "eventId": "ev_key_transfer_01",
  "projectId": "book_fog_harbor",
  "routeId": "route_main",
  "sceneId": "scene_03",

  "kind": "item.transfer_possession",
  "itemId": "item_brass_key",
  "fromEntityId": "character_linwu",
  "toEntityId": "character_shenyan",
  "reviewState": "confirmed",
  "evidence": [
    { "documentRevisionId": "docrev_31", "blockId": "p_08", "quote": "林雾把黄铜钥匙交到沈砚手里。" }
```

正式记录还需正文内容哈希、锚点偏移、操作者及约束版本。编辑器的 UTF-16 位置与证据持久化偏移须明确转换，中文扩展字符和 emoji 不能错位。

## 5. 元素更新闭环

```text
作者保存/采用正文 → 产生内容修订 → 抽取候选与证据 → 实体消歧
                 → 与既有状态核对 → 章节级审阅 → 提交知识修订
                 → 写入索引更新事件 → 重建受影响投影与检索片段
```

### 5.1 不制造设定维护负担

- 每章展示“新增元素、关系变化、状态变化、冲突”四组，不为每一句描写弹窗。
- 精确引用可以自动建立为可撤销的提及索引；确立世界事实仍与提及索引分开。
- 低风险重复断言去重，已确认的同一事实不反复要求确认。
- 批量确认展示实际改变的字段和对应证据；模糊人物映射、秘密、死亡、唯一物品转移等高影响项单独突出。
- 作者也能手动维护或先只写作；待整理状态可见。尚未整理的正文仍可作为原文证据检索，但不冒充已确认的结构化事实。

### 5.2 修改、撤销和删除

- 改写引用原文后，旧抽取与摘要标记“源已变更”，不能仍以确认状态代表当前稿件。
- 仅引用了没改动的稳定段落可在哈希一致时复用；整体重排不能依靠字符位置猜测锚点。
- 部分接受候选后，对实际采用文本重做抽取；没有采用的状态变化不得入库。
- 撤销生成或删除场景不会抹去历史版本；当前快照不再引用的事实退出当前检索。
- 作者直接设定没有正文证据也可确认，但应标注“作者设定”而不是虚构引用。
- 作品彻底删除须涵盖正文、附件、向量、摘要、任务产物与日志中的内容副本，备份保留单独说明。

### 5.3 AI 角色与世界观共创（双模式）及秘密知情规划

作者在新建或扩展元素时，可使用 **快速卡片共创**（输入一句话直接生成 2–3 张方案卡）或 **一步步问答引导**（宿主状态机推进 2–3 道结构化选择题后再生成方案卡）。

- 模型通过只读工具检查既有元素与事实，避免同名撞车或设定冲突；输出的方案卡保存为 `artifacts` 中的不可变 `candidate` 产物，不直接写库。
- 作者可跨方案卡借用字段（如借用方案 B 的“核心阻碍”或某条关系提案）、手动修改文本，并勾选要一并入库的初始属性事实与关系。确认采用后，宿主在同一事务中创建/更新 `elements`、`character_arcs` 与 `kw_facts`（标记 `sourceKind = "author_setting"`），立即可供后续检索与一致性检查使用。
- 针对 `secret`（秘密/伏笔）元素，AI 辅助同时设计**世界真相（`world_fact`）**、**表面假象/角色误信（`belief`）**、**初始知情者（`known_by`）**与**预计揭晓条件/时点（`revealed`）**，并在元素详情页提供可视化知情区间编辑，直接驱动 §6.5 的知识边界过滤。

### 5.4 正文反向抽取与证据锚定契约（`extract_ledger`）

对于“先直接写正文”或导入旧稿的章节/场景，作者可主动触发 `extract_ledger` 任务：

- 模型扫描目标场景已采用正文（`manuscript`），输出新元素候选、属性/关系事实提案与状态事件提案，每项必须附带正文原句 `quote`。
- **宿主确定性证据核验**：宿主在目标场景当前修订的正文段落中精确查找 `quote`，按 `作品 + 修订 + 场景 + 段落 + 内容` 生成确定性 `evidenceId`；找不到匹配原文的幻觉抽取项不得作为正文证据事实入库。
- 作者在设定整理审阅单中勾选确认后，经 `ChangeSet` 与基础修订 CAS 一次性写入权威账本。

## 6. 混合 RAG 管线

### 6.1 混合检索与计划上下文

1. **结构化查询**：查准确实体、有效属性、关系、物品状态、知识状态、规则与事件链。
2. **关键词检索**：命中人名、别名、术语、引号原句、具体物品；支持中文分词与短名称索引。
3. **语义检索**：找“前一次信任崩塌”“类似的争执”“这个地点的气味”等不包含完全同词的片段。
4. **计划视图查询**：在前三种检索旁，直接读取已选计划与相关场景目标；这是领域视图，不是第四个检索引擎，也不是已发生事实。

结构化结果负责约束；检索片段提供依据和文风。低相似度、缺少证据或来源冲突时返回“不确定/未找到”，不由检索器自行补事实。

### 6.2 上下文构建步骤

```text
解析任务目标、目标场景、POV
→ 固定作品清单、分支、路线、故事时间、阅读可见边界
→ 解析实体与别名
→ 读取当时状态、前置条件、规则和必要事件链
→ 按用途取用选定计划（标拟发生）与作者显式保存的作品偏好
→ 在允许的源修订集合内做关键词/向量召回
→ 用关系邻居扩展必要线索，限制跳数和数量
→ 排序、去重、补充上下段，核验证据仍有效
→ 按上下文预算组装并展示来源
→ 固化 ContextSnapshot，交给任务执行器
```

建议初始参数：关键词和语义各召回 20–40 条，融合后保留 12–20 条候选；最终条数受文本长度与任务影响。参数通过中文小说评测调整，不作为固定正确答案。

作品早期的知识库可能为空，这是正常状态。不为了凑足条数引入无关材料，也不向公共小说库借正文或默认套用他人文风；检索不到就按未找到呈现，由已选内容与作者输入支撑当次创作。

### 6.3 过滤是正确性条件

检索前由权威存储计算允许的 `sourceRevisionId` 集合：作品、可达修订、故事路线、知识可见性、材料授权范围。索引查询预过滤，返回后再由权威层验证一次。

不能只筛 `branchId = 当前分支`，因为分支可能继承祖先内容；也不能把同一本书全部旧稿召回后直接交模型判断真伪。

选定计划按**用途**进入或退出上下文，不是一律可见或一律隐藏：规划任务与按场景目标限定的写作任务可取用拟发生的计划；事实核对与角色知识检查不把它当作已发生证据；未来秘密仍受知识边界约束，选定计划不绕过该过滤。细则见[技术架构](<ARCHITECTURE.md>) 6.9。

不把前端传来的任意 SQL 或字段表达式直接拼进检索。LanceDB 的过滤和 SDK 版本行为须按[官方过滤文档](<https://docs.lancedb.com/search/filtering.md>)核对；旧版本连续调用 `where` 曾有覆盖前条件的差异，统一生成一个经过校验的完整谓词更稳妥。

### 6.4 分块与索引

- 先按场景和段落边界切分，再控制长度；不把相邻章节或不同路线混成一个块。
- 每块存作品/源修订、场景、段落范围、实体引用、叙述位置、可见范围、内容哈希。
- 场景摘要是派生数据，保留摘要来源与覆盖范围；不是可以脱离原文永久成立的事实。
- 首版选定计划通过结构化/关键词计划视图读取，不进入正文向量索引；若后续需要语义搜索大纲，使用独立来源分区和用途过滤，不能混作文风样本或已发生证据。
- 嵌入索引命名空间包括模型标识、版本、向量维度与预处理版本；换模型新建索引，不混用旧向量。
- 向量库推荐候选为 LanceDB OSS；权威关系仍在 SQLite，索引可从原文与清单重建。
- 中文关键词不能直接假定 SQLite `unicode61` 有中文分词能力；它按连续字符类别分词。当前实现对正文做单字预分词后写入 FTS5，查询串同样按字切分，因此“沈砚”这类二字名称能被命中；`trigram` 不匹配少于三个字符的全文查询，不能独自承担二字名称检索。依据：[SQLite FTS5](<https://www.sqlite.org/fts5.html>)。

### 6.5 人物知识与作者秘密

至少提供以下上下文策略，可按任务继续扩展：

| 任务 | 可见信息 |
| --- | --- |
| 总体规划/因果分析 | 作者允许的全知设定、计划和路线；分区标注未发生事件 |
| 场景正文/人物对白 | 当时状态、POV 已知内容、当前允许的揭示；排除不该获知的未来原文 |
| 按选定计划写作 | 与当前场景目标相关的选定计划，标为拟发生；未来秘密仍排除 |
| 读者视角检查 | 截至当前叙述位置读者可获得的线索，不使用作者秘密推断“明显答案” |

必要的作者秘密优先由规划层转译为约束，例如“此处保持身份未揭示”，而不是把“真凶是谁”连同一句“不要说”直接塞入对白生成上下文。角色可以持有错误信念；生成对白时使用其信念，审校时与世界事实对照。

### 6.6 上下文面板与预算

面板按“必须遵守的状态/规则、当前场景、计划（拟发生）、作品偏好、历史原文、相关情节、文风材料”分组，每条可看原文、版本和为什么被选中。

作者偏好只在作品范围内显式保存，不从一次拒绝推断永久画像。历史原文可作证据或作者指定的风格参照，但默认不逐句套写；必要照应、刻意重复与无意复用分别呈现，由作者决定。事实复用不等于自动复用漂亮句子。

上下文预算先预留模型输出和协议开销，再分配输入；必须约束优先。若必须内容也超限，提示缩小任务或选择更合适模型，不静默丢掉关键事实。CLI 不提供实际窗口/token 统计时显示估计值与不确定范围。

作者可固定/排除证据，固定项也要经过版本和权限校验。展示模型实际发送清单，不只显示“本书已加入知识库”。

## 7. 一致性检查

### 7.1 三层检查器

| 层 | 能处理 | 输出 |
| --- | --- | --- |
| 确定性规则 | 唯一物品重复持有、数量负数、时间先后冲突、字段约束 | 可复现问题，附规则与输入 |
| 证据约束的语义检查 | 称呼、身份、动机、知识泄漏、描述冲突 | 候选问题及支持/反驳原文 |
| 作者判断 | 不可靠叙述、魔法例外、故意误导、艺术留白 | 确认问题、声明例外或驳回 |

死亡不必永远禁止再出现，物品复制不必永远非法：这些由作品规则决定。检查器不得把现实常识强加到所有题材。

### 7.2 规则包建议

- **身份**：别名混淆、同名误合并、称谓与关系不匹配。
- **物品**：所有权/占有/位置、唯一性、消耗、损坏与修复。
- **人物**：伤势、能力、年龄、行程、身份变更与关系状态。
- **知识**：未获知却引用秘密、遗忘后仍当作已知、读者线索提前泄漏。
- **时间**：事件前后矛盾、行程时间不足、并行场景冲突。
- **数量**：库存、金钱、能量、使用次数的收支与单位。
- **世界规则**：能力触发条件、代价、例外的适用范围。
- **叙事**：伏笔未回收、回收早于铺垫、承诺情节遗漏；标为创作提醒而非必然错误。

### 7.3 问题的可解释结构

`Issue = 检查对象 + 基础版本 + 当前证据 + 冲突证据 + 规则/判断 + 严重度 + 确定程度 + 修复候选 + 检查覆盖范围`。

模型未找到矛盾不代表“全文无逻辑问题”。报告显示已检查章节、已构建状态比例、待确认事实及无法判定的时间区间。

作者处理结果分为“已修复、抽取错误、世界规则例外、有意保留、暂缓”。例外绑定具体规则与范围；新证据改变前提时重新打开问题，而不是永久忽略同类错误。

### 7.4 问题分级与处理边界

检查结果按三级呈现，边界与自动推进规则见[技术架构](<ARCHITECTURE.md>) 6.8：

| 级别 | 例子 | 处理 |
| --- | --- | --- |
| 已确认约束冲突 | 同一故事时点，同一双唯一鞋既“仍在柜台”又“已交给外地顾客” | 标出冲突依据；合入前解决，或修改旧设定、声明例外、另存路线 |
| 因果缺口或未知 | 决定把鞋送回去，但不知道地址；顾客是否还在世未知 | 提示缺少线索；允许暂缺，记为未知，不判错 |
| 审美建议 | 连续两场都在争论同一件事 | 可选提醒；作者可以认为重复具有意义 |

模型评分不能代替作者决定。已授权的检索、检查、候选生成可自动推进；批量接受是作者对可见清单的明确选择，其后可自动提交事务。未知与审美观察不升级为硬冲突，真实约束/版本冲突与数据出站权限仍须处理。

## 8. 贯穿示例：黄铜钥匙

以下为原创测试故事片段。

### 8.1 钥匙示例

| 场景 | 阅读位置 | 故事时间 | 已确认事实 |
| --- | --- | --- | --- |
| S03 | 第三章 | 第一天 21:10 | 林雾将唯一黄铜钥匙交给沈砚 |
| S05 | 第五章的回忆 | 第一天 08:00 | 林雾用该钥匙打开仓库 |
| S08 | 第八章 | 第二天 09:00 | 钥匙从沈砚口袋落入河底，尚未打捞 |
| S10 | 第十章 | 第二天 10:00 | 待写：沈砚进入仓库 |

正确行为：

1. 写 S05 时读取第一天 08:00 的状态，钥匙在林雾处；不能因已读 S03 就误报。
2. 写 S10 时返回“钥匙不在沈砚手中、位于河底”；所有权可仍属于沈砚，占有关系已结束。
3. 候选稿写“沈砚掏出黄铜钥匙开门”，检查器引用 S08，指出缺少取回/替代事件。
4. 修复候选：补打捞情节、改用其他进入方式，或由作者修改旧设定；不自动凭空生成备用钥匙。
5. 若“未丢钥匙”只存在于修订分支 B，主稿不能检索到该状态。
6. 林雾没目睹遗失，可以误以为沈砚仍持有钥匙；其对白不因此判为世界事实冲突。

### 8.2 来源种类示例：十年前的收据

以下为原创虚构样例，用于说明同一作品内不同内容的状态差异。

一个年轻人准备关掉父亲的旧修鞋铺，发现一张十年前未取鞋的收据。

| 内容 | `sourceKind` | 可见范围 |
| --- | --- | --- |
| 未采用的点子卡：“把鞋送回去”“把这笔账问清”“做完最后一单” | `candidate` | 持久保存在产物库，经显式引用用于比较/组合/试演；不进入正式事实或普通索引 |
| 作者选定“主角仍会关店”，并借用“父亲不赞成寻找顾客” | `selected_plan` | 规划任务与按该场景目标的写作任务可见，标为拟发生；事实核对不采信为已发生 |
| 试演片段：“父亲伸手要看那张十年前的取鞋单” | `candidate` | 只作生成输入，不进正文检索 |
| 已采用的正文段落 | `manuscript` | 可检索的原文证据；从中抽取的事实仍待确认 |
| 作者直接写下“父亲健在” | `author_setting` | 已确认事实，标为作者设定；无正文锚点也不算虚构引用 |

关键行为：

1. 试演可以按作者选定的“父亲健在”暂定前提写作，并标为计划假设；事实问答不能据此声称该设定已确认。若与现有死亡事实冲突，需修改计划、正式调整设定或另存路线。已采用正文也须区分叙述事实、对白与错误信念。
2. 作者另行保存的未来秘密，对该场景仍按知识边界隐藏，选定计划不绕过这一过滤。
3. 知识库为空属正常状态：依据作者输入与选定计划创作，不凑召回、不虚构证据。
4. 候选卡与试演在比较任务中列为候选输入，不混入普通正文 RAG 的事实证据清单。

## 9. 与画布、Agent、版本的联动

- 场景卡显示进入状态与计划变化；进入元素详情可沿证据返回正文。
- 剧情节点移动故事时间后，重新计算受影响元素状态，并把相关生成结果标记待复核。
- 工作流“读取状态 → 检索 → 生成 → 抽取变化 → 检查 → 审阅 → 提交”使用同一快照标识。
- Agent 获取结构化读接口，不直接改知识表；写操作是 `proposeFacts` / `proposeChanges`，提交由宿主完成。
- 合并分支同时合并事实/事件，重算时间线；不能只合并文字。
- 历史版本问答读取历史知识清单；“现在是否正确”与“当时作者认为什么”分别回答。

### 9.1 Pi 领域工具桥

默认通过本平台的 Pi 扩展注册小说工具；以下名称是拟设计的领域接口，不是 Pi 内置 API：

| 工具 | 作用 |
| --- | --- |
| `novel_get_scene` | 读取绑定作品修订中的场景与正文 |
| `novel_get_world_state` | 查询路线、时点和 POV 对应的元素状态 |
| `novel_search_context` | 在宿主限定范围内混合检索，返回带证据的上下文 |
| `novel_propose_changes` | 提交正文/元素/剧情修改提案，不直接合入主稿 |
| `novel_check_consistency` | 返回规则与语义问题单 |

扩展从宿主获得任务级能力句柄，作品、分支、路线、可读修订和写入范围由宿主绑定；不能由模型传入更大的范围自我授权。正式提交保留在 GUI 审阅后的宿主事务中。

### 9.2 Pi 会话记忆不能取代知识库

Pi 对话、压缩摘要与会话分叉可能包含未采用候选、另一分支或未来秘密。它们作为过程记录保存，不能自动进入作品 RAG。

同一会话复用须核对 `projectRevisionId + routeId + perspective + knowledgeBoundary`。场景写作与全知规划默认分会话；切换路线或信息边界默认创建新会话。仅在旧会话末尾追加“忘记之前的信息”不能实现隔离。Pi 进行压缩后重新检查状态绑定，必要时从权威层构建新上下文。

## 10. 索引一致性、隐私与恢复

权威提交与 outbox 在同一 SQLite 事务完成；索引 worker 消费更新、校验源版本、写派生索引，再推进水位。迟到旧任务不能覆盖新修订索引。

索引暂时不可用时保留结构化与关键词能力，明确标记“语义检索不可用”；若本任务要求完整检索，则等待修复而非把降级结果伪装成完整检查。

远程嵌入会发送正文片段，不能因为数据库在本机就称为全离线。嵌入与生成分别配置提供方、数据范围和费用。首次全书建索引展示预计文本量与成本；默认不自动上传所有附件。重排模型亦适用同样的数据范围控制。

备份包含事实/事件/引用和原文；向量可选择携带或恢复后重建。导出元素时提供带稳定 ID 的 JSON 与便于编辑的 CSV，CSV 附字段/关系说明；不能只导出一张丢失历史的角色表。

## 11. 专项验收数据集

| 编号 | 用例 | 期望 |
| --- | --- | --- |
| K01 | 两个同名角色，同一物品有复制品 | 不静默合并，分别追踪引用 |
| K02 | 变更发生在后章，前章为倒叙 | 按故事时间还原状态 |
| K03 | 作者秘密未向 POV 揭示 | 场景/对白检索不带入秘密原文 |
| K04 | 角色相信谣言，与世界事实不同 | 标记信念差异，不误报硬冲突 |
| K05 | 物品借出后遗失 | 所有权、占有、位置分别正确 |
| K06 | 修订分支 B 的状态更“相似” | 仍不进入主稿检索结果 |
| K07 | 废弃旧稿的向量尚未物理清理 | 权威可见性过滤阻止泄漏 |
| K08 | 只接受候选中的一段 | 未采用部分的事实不提交 |
| K09 | 时间不明、数量单位不明 | 返回未知或待确认，不假定正常 |
| K10 | 原文引用位置改变或被删除 | 锚点重定位须有证据；否则标失效 |
| K11 | 嵌入模型切换维度 | 新建索引，不混用；旧索引可回退 |
| K12 | 两字人名、昵称、错别字查询 | 两字人名与昵称经中文按字的关键词索引召回；错别字与近义要靠语义通道，当前未配置，明确标为不支持而不是假装命中 |
| K13 | 世界规则允许分身、复活、物品复制 | 按已确认规则检查，不机械套常识 |
| K14 | 同时发生的互斥事件、顺序未知 | 不按记录顺序任意选结果 |
| K15 | 知识确认后正文再次改动 | 源已变标记传播到摘要、状态和上下文 |
| K16 | 点子卡与候选批次 | 保存在 `artifacts` 的不可变产物；`card_revision` 单调递增，旧版本仍可被历史选择快照引用 |
| K17 | 选卡、改卡、锁定、撤销 | 每次都使 `selection_version` 递增并写新的选择快照；撤销不重复调用模型 |
| K18 | 采用时分支头或选择草稿版本已变 | 同一事务内回滚；过时产物保留，不覆盖分支头 |
| K19 | 跨卡借用某一项 | 被借字段记录来源卡与局部三方差异，可区分借用内容与本卡原有内容 |
| K20 | 语义锁定与原文保护 | 分别记录、分别比较；解除不由模型评分决定 |
| K21 | 按选定计划写作 | 相关计划可见并标拟发生；事实核对不采信为已发生；未来秘密仍隐藏 |
| K22 | 知识库为空 | 返回未找到或稀疏状态，不凑 TopK，不引入外部小说正文 |
| K23 | `candidate` 用于比较或试演 | 只能经显式引用作为候选输入；不进入普通正文 RAG 的事实证据清单 |
| K24 | 显式复用旧产物与重新生成 | 产物与任务记录可区分两者；采样配置不可得时留空，不声称已控制随机性 |

评估至少包括：实体消歧准确率、相关证据 Recall@10、引用有效率、可判定冲突召回与误报、跨分支/未来信息泄漏率、索引更新延迟。测试集包含正常段落与刻意埋入的错误，避免只用明显矛盾获得虚高成绩。
