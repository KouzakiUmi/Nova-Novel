# 新手创作体验：评审依据与设计示例

> 2026-10-27 · 主线已纳入 v1.1 正式设计
>
> 本文保留四个视角独立评审与交叉讨论形成的依据和创作示例。三条起步路径、卡片组合、按需试演、局部推敲、内容分层与 N 系列验收已纳入[正式产品方案](<../DESIGN.md>)。数据契约以[运行架构第 6 章](<ARCHITECTURE.md#L108>)为准；效果和界面参数仍待真实用户验证，尚无应用实现。

## 1. 总结：需要优化，但不是再堆一层 Agent

**评审发现的重点是：可靠的创作管理还需要配上“帮助新手开始并作出选择”的体验。v1.1 已把这一层与原有技术底座结合。**

正式方案采用的默认创作路径为：

```text
一个兴趣或点子
→ 看懂几张不同的故事建议卡
→ 选、改、借用其中一个点子
→ 看一小段试演
→ 决定人物接下来做什么
→ 写出/采用一场戏
→ 按需推敲一处
→ 保存自己的版本，继续下一场
```

新手可能不懂“POV、人物弧、情绪转折”，但通常知道自己想看什么、不喜欢什么。产品应把这种读者判断转换为创作选择，而不是要求先学会填专业表格。

核心建议：

1. **默认入口是可跳过的创作起步页。** 双画布、元素库和版本能力仍在，按需展开，不改成必填问卷。
2. **大纲建议做成可组合、可试演、可局部替换的点子卡。** 不是把三个长篇大纲分别放进卡片容器。
3. **先帮助决定“发生什么、人物为什么这样做”，再处理语言。** 去掉几个常见词不能补救空洞的动机。
4. **“没有 AI 味”转化为具体创作目标。** 不提供“人类概率”，也不把克制、短句、留白奉为唯一好文风。
5. **保住已选方向和个人取舍。** 换一张建议不重写整个故事；修改措辞不偷偷更换人物命运。

## 2. 评审关注与正式落实

### 2.1 应保留的底座

- 候选稿不覆盖正文，支持部分采用、分支与差异审阅。
- 剧情图与执行图分离；降低界面复杂度不需要删去任一画布。
- 元素属性、关系和变化有证据与时态，能够支持长篇前后一致。
- Pi 会话历史与作品版本分离，未采用点子不会自动变成正稿事实。
- 低风险检索、摘要、检查可在后台完成；作者掌握创作决定。

这些机制是优化的基础，不需要换内核或再引入一套 Agent 框架。

## 3. “没有 AI 味”究竟优化什么

这里把它理解为：**减少可替换的套路表达，让故事里的选择、细节和说话方式符合本作品。** 它不是文本来源鉴定，也没有保证所有读者认同的单一分数。

| 可观察现象 | 更有用的问题 | 产品怎样帮忙 | 不应机械处理 |
| --- | --- | --- | --- |
| 人物只按剧情需要行动 | 他为什么现在愿意做这件事？ | 提供不同动机及其后果的短卡 | 强迫每场戏都有惨痛代价 |
| 事情靠连续巧合发生 | 上一步怎样改变了下一步？ | 展示“因为/但是/于是”的连接预览 | 每章必须有反转 |
| 所有人说话同一个口气 | 他想从对方那里得到什么？ | 按关系与目的试演同一段对白 | 靠口头禅给每人贴标签 |
| 情绪被反复总结 | 这里需要说明，还是让行动表达？ | 同事实、不同表现手段的对照 | 删除所有情绪词 |
| 细节换任何作品都适用 | 这个东西会影响人物的动作吗？ | 从场景、职业与已选设定中取细节 | 为“真实”随机添气味和杂物 |
| 段段节奏相同、结尾都总结 | 这段应推动、停留、解释还是兑现？ | 按本场目标提出一处可选调整 | 全部改短句、口语或留白 |
| RAG 反复召回同一漂亮句 | 这是必要照应，还是表达重复？ | 区分事实复用、意象回响与原句复用 | 把历史文字当每段必套模板 |

抒情、爽感、直白说书、喜剧和缓慢观察都可以成立。软件帮助作者看见影响，不替作者选定统一审美。

## 4. 已采纳的新手入口及示例

### 4.1 三条平等路径

| 入口 | 适合谁 | 接下来发生什么 |
| --- | --- | --- |
| 帮我找个开头 | 没有完整点子，只知道兴趣或感受 | 给少量短建议，也可先浏览原创示例 |
| 我有一个点子 | 已有一句话或一个画面 | 保留这句话的核心，只补当前缺的一步 |
| 我直接写 | 想从正文、对白或粘贴片段开始 | 编辑器直接可用，之后可反向整理场景卡 |

不要求先写满 150 字，不要求先连接所有 CLI，不要求先做人物档案。已有系统语音输入可以作为文本输入方式；独立语音引擎不是这条闭环的前提。

### 4.2 首屏文案示意

```text
你想从哪里开始？

[ 一句话、一个人物，或者一个画面……                    ]

例如：关掉父亲旧修鞋铺前，他发现一张十年前未取鞋的收据。

[给我几个开头]     [围绕这个点子继续]     [直接写]

也可以打开一个示例故事，看看文字怎样变成场景卡。
```

先给创作动作，术语解释在用到时出现。示例为虚构素材，不要求作者提供真实家庭经历。

### 4.3 第一场戏的路径

1. 看几张短卡，选择、编辑或提出第四种方向。
2. 可选回答一个具体问题，例如“他更想赶紧关店，还是先弄清这张收据？”
3. 选中后可展开小段试演；不自动生成三篇长文要求比较。
4. 作者可采用、局部改写、另写或继续构思。没有意见、全部保留也是有效选择。
5. 有文字后，AI 提议反填场景卡和元素；展示“从哪里看出来的”，允许纠正和暂缓。
6. 保存可恢复版本，问“接下来想写哪一步”，不立刻要求规划全书。

建议用少量候选、短试演作为原型起点；候选数量、字数与完成时间均须测试，不作为已验证的最佳值。

## 5. 卡片式大纲：组合的是创作选择

### 5.1 三种卡片对象不要混淆

| 对象 | 用途 | 何时出现 |
| --- | --- | --- |
| 点子卡 | 尚未采用的行动、动机、阻碍、结果建议 | 构思与替换阶段 |
| 场景卡 | 作品计划中一个场景的稳定对象 | 作者将点子放入计划后 |
| 工作流节点 | 调用检索、Pi、审阅、提交等任务 | 展开高级编排时 |

点子卡可以是场景某个字段的候选，也可以组合成多个场景；它不是执行节点。新手不必理解端口、schema 或 DAG。

### 5.2 卡面只表达三件事

- **会发生什么**：一句具体行动，不只是“温暖治愈”“命运反转”。
- **为什么值得选**：这条路关注什么关系、悬念、冲突或感受。
- **选它要接受什么**：会失去的机会、带来的麻烦或对节奏的影响。

可展开信息：暂定的新设定、依赖哪张卡、与已选方向的差异、一小段试演。不是每张卡都必须有秘密、伏笔、反转或情绪曲线。

### 5.3 必备操作

| 操作 | 行为 |
| --- | --- |
| 保留这一点 | 锁定一个创作决定，不强制锁死全部措辞 |
| 只换这里 | 以其余已选内容为约束生成新候选，旧批次仍可找回 |
| 借这个点子 | 从另一张卡取一个动机/障碍/场面，预览组合影响 |
| 看看写出来怎样 | 生成可丢弃试演，标为候选，不写入正稿 |
| 我来改/加一张 | 自写卡与 AI 卡同权，未填字段可以保持未知 |
| 这次不想要 | 只影响当前批次；可选择保存为本作品偏好，随时取消 |
| 撤销/回到上一组 | 恢复选择与组合，保留历史产物，不重复付费生成 |

“保留含义”与“保护原句”分开：前者防改变剧情决定，后者防改动特定文字。默认不预选“最佳卡”，也不显示“你只采用了几张”给作者施压。

### 5.4 三个候选怎样真正不同

优先改变**主角的行动、面对的阻力和承担的取舍**，而不是只改名称、形容词和场景颜色。

可以从人物欲望、一个疑问、一个结尾画面分别构思，但算法策略不必出现在卡面。候选不是必须相互对立，作者可以组合；差异必须能用普通语言解释。

不强制所有候选更曲折。一个“不揭露大秘密、只做完一件小事”的方向，同样是合法选择。

## 6. 完整例子：一张未取鞋的收据

### 6.1 固定输入与暂定内容

已给输入只有：一个年轻人准备关掉父亲的旧修鞋铺，发现十年前未取鞋的收据。父亲是否健在、顾客是谁、为什么没来取，都尚未知。

下列内容是**可选计划建议**，不是系统替作者确立的背景。

### 6.2 第一组方向卡

| 卡片 | 行动与阻力 | 这条路关注什么 | 取舍 |
| --- | --- | --- | --- |
| A 把鞋送回去 | 关铺前寻找取鞋人；收据上的联系方法已经过时 | 一次拜访、人与旧物的关系 | 要把时间留给一件可能无人需要的事 |
| B 把这笔账问清 | 向父亲询问为什么一直留着这一单；两人对“关店”避而不谈 | 一场具体的父子/父女对话 | 必须面对彼此对旧店的不同期待；父亲健在是新增建议 |
| C 做完最后一单 | 在关店前修好这双旧鞋；主角的能力是否够用由作者选择 | 手艺、失败和完成一件事 | 未必保住店，也未必得到顾客感谢 |

三个方向分别通过外出行动、关系对话、手上工作推动故事，不靠换一套抒情词伪装成不同方案。

### 6.3 从 A 借用 B，而不是拼接整篇大纲

示例中的作者选择 A，但借用 B 的“父亲不赞成寻找顾客”，并明确接受“父亲健在”这一计划。作者另外选定：**主角仍然会关店，不写成继承父业的结局。**

接下来只补“什么让他真的出门”这一块：

1. 父亲觉得这单已经结清，年轻人却想按收据把东西处理完。
2. 年轻人发现鞋已经修好，只差交还；继续放着和直接丢掉都不合心意。
3. 顾客先联系过来，但要的不是鞋，而是确认这家店是否真的要关。

作者可以保留第 2 点、改第 1 点、不要第 3 点；这就是卡片组合，而不是重复生成整份大纲。

### 6.4 组合后的“故事接龙”预览

```text
他准备清空旧店
→ 发现一双已修好但未取走的鞋
→ 不愿直接丢弃，决定尝试交还
→ 父亲不赞成继续花时间，两人发生分歧
→ 他去寻找顾客，也为清空旧店留下更少时间
→ 后续结果暂未决定；“仍会关店”保持锁定
```

界面提问：“父亲为什么不赞成？”并给“现在补一下 / 暂时留空 / 我自己写”。不为补齐因果自动生成父亲去世、身份反转或大团圆。

### 6.5 三类提示

| 情况 | 示例 | 产品动作 |
| --- | --- | --- |
| 已确认约束冲突 | 同一故事时点，同一双唯一鞋既“仍在柜台”又“已交给外地顾客” | 标出冲突依据；合入前解决，或修改旧设定/另存备选路线 |
| 因果缺口或未知 | 决定送鞋，但还不知道地址 | 提示缺少线索；允许暂缺，不把未知判为错误 |
| 审美建议 | 两个连续场景都在争论同一问题 | 可选提醒；作者可以认为重复具有意义 |

草稿区允许探索矛盾。强制校验保护的是提交与已锁定约束，不是阻止作者记下任何怪点子。

### 6.6 换掉上游卡时

若作者把“寻找顾客”改成“等顾客上门”，系统说：“出门路线和途中场景可能不再需要”，并列出受影响卡片。支持保留并标待核、重做选中部分、移到备选。不会整图重写，也不把未检查部分标为已一致。

## 7. 从大纲到正文：自然感来自选择，不是洗词

### 7.1 先明确这一场想做什么

不要求新手填“主题表达”。可以问：“这场你更想让读者看到他急着关门、放不下旧物，还是与父亲意见不合？”允许多选、自己说、暂不决定。

本作品偏好卡只记录作者明确选定的内容，例如：愿意直说情绪、喜欢带一点幽默、不想靠重病推动剧情、保留某句对白。它不是跨作品的永久性格画像，也不从一次拒绝自动推断作者风格。

### 7.2 一次推敲一处

复用现有“推敲/写作搭档”，不增加独立审校 Agent 或必经节点。作者打开时，优先提出一条与当前目标相关的问题：

> 这里连续两句都在解释“舍不得”。你想把情绪直接说清，还是让他处理收据的动作多承担一点？

提供定位原句、一个可选试演，以及“保留原文 / 用这个方向 / 我来改 / 暂时不处理”。下一条按需出现，不自动循环直到模型给出高分。

### 7.3 同事实、不同写法

本微例固定事实：年轻人准备关店；父亲在柜台对面；发现十年前的取鞋单；父亲伸手；年轻人把单子压到交接清单下面，并说“先点工具吧”。

**更直接说明情绪：**

> 父亲伸手要看那张十年前的取鞋单。他怕一问，今天又关不了店，便把单子翻过来，压在交接清单下面。“先点工具吧。”他说这话，是不想再谈关店的事。

**更多交给动作表达：**

> 父亲伸出手。他看了一眼取鞋单上的年份，把纸翻过来，压进交接清单底下。“先点工具吧。”

前者清楚、直接；后者更省略，也可能让某些读者觉得信息不足。不存在“第二版天然更高级”。这是选择表现手段，不是证明哪版由人写成。

语言修改保留已确认事实和明确保护项。试演若提出关键新人物、物品归属、死亡或身份变化，要列为新增剧情建议；普通动作细节不必逐字弹窗。创意扩写和只改措辞是两个可见模式。

### 7.4 停止条件

作者满意、选择先继续写、没有新的可定位问题，或本次试演额度用完，即可结束。停止不要求作者改过字、拒绝过建议或获得某个分数。整章完成后再做结构复查，避免每写一句就进入审校。

## 8. 还值得做的辅助设计

| 想法 | 具体用途 | 建议阶段 |
| --- | --- | --- |
| 可拆开的原创示例作品 | 同屏看一段正文、场景卡、一个元素变化和它的依据 | 首批验证 |
| 卡住时的三种帮助 | “不知道发生什么 / 知道情节但写不出 / 写出来不满意”分别进入点子、试演、推敲 | 首批验证 |
| 反向整理 | 作者先写，AI 再提议场景卡和人物关系，避免先填表 | 首批验证 |
| 人物对白试演 | 同一目的与事实下比较两种应对，不靠口头禅区分人物 | 适度扩展 |
| 原创细节素材盒 | 收藏观察、虚构细节或获授权资料，指定本次是否使用 | 后续验证；带来源和隐私范围 |
| 读者信息视图 | 展示截至这里读者知道什么、仍在等什么答案 | 复用现有知识边界后渐进呈现 |
| 局部备选试写 | 改一个决定，只试演受影响场景，不复制整本小说 | 复用版本和分支能力 |
| 可选技巧解释 | 看过试演后点“为什么会这样”，给一句说明与本段例子 | 按需，不做必修课程 |

独立语音引擎、社区点评和自动学习个人风格需要额外产品验证，不作为降低第一次写作门槛的必要前提。

## 9. 怎样接入现有 Pi、RAG 和版本系统

### 9.1 不建立第二套写作数据库

新手/进阶是同一对象的不同视图。点子卡作为候选产物保存；采用后生成既有 `StoryGraphPatch`，进入场景与剧情计划。正文采用仍走 `ChangeSet` 和版本比较。

字段和并发规则已落入[正式数据契约](<ARCHITECTURE.md#L108>)，此处不再维护另一份 schema。核心是：批次与卡片为不可变产物；选择草稿有宿主侧单调版本；生成冻结作品版本、正式计划投影、当前选择、意图与上下文；采用时同时核对作品头与选择版本。

`baseRevisionId + basePlanHash` 直接引用既有作品计划，不新建计划版本树。`authoring_drafts` 仅协调选择快照和 CAS，不复制小说数据。旧批次、借用来源与明确的复用行为均可追溯。

### 9.2 四种内容状态

```text
未采用点子：只在候选比较/组合任务中可见
选定计划：可供规划、场景目标与试演使用，明确标为“拟发生”
采用正文：当前稿件证据，可检索；抽取出的事实仍可能待确认
已确认设定/事件：在对应时点、路线和修订中作为约束
```

作者直接手写确认设定也是合法入口，不需要等 AI 抽取。选定计划不能冒充已经发生的事件，但也不能一概从写作上下文删除，否则 AI 无法按大纲写作。

### 9.3 空知识库也能开始

新作品先用作者输入、选定计划和少量明确设定，不为了凑足 Top-K 召回无关材料。历史证据为空是正常状态，不自动向公共小说库借正文或建立“其他作者文风”默认模板。

随着采用正文逐步积累，后台建立提及和检索索引；高影响关系、时间和状态变化以聚合摘要审阅。不是每出现一张桌子都要求建元素档案。

### 9.4 Pi 任务边界

- 卡片生成、组合试演、语言推敲使用现有 Pi 能力和职责模板，不各开一个永久人格。
- 每次任务绑定作品/计划修订、选择哈希、约束和知识视角；已有 Pi 版本与会话边界继续适用。
- 生成期间作者改卡或取消任务，迟到结果进入旧批次，不替换新选择；采用前做基础/当前/候选比较。
- 新请求记为新尝试，重复网络投递以幂等键去重。显式复用与重新采样分别显示，不用编辑距离保证“更不同”。
- 合并候选导致上下文边界变化时新建合适会话，未采用方案不泄漏到后续正文。
- 已授权的检索、摘要和候选生成可以自动推进；写入正式计划、正文、事实或版本的创作决定不能由模型评分代替。

### 9.5 降低确认负担而不跳过决定

用一张“这次将改变什么”汇总正文、计划与元素变化，允许逐项展开、批量接受或稍后处理。数量目标只用于研究交互负担，不以“已经弹了三次”跳过事实冲突、出站权限或版本冲突。

## 10. 交叉讨论后的取舍

| 候选做法 | 最终建议 | 原因 |
| --- | --- | --- |
| 先让作者写够一段，再开放 AI | 三种入口并行 | 练习可以帮助，但不应成为不会写者的门槛 |
| 首屏展示三段完整试写 | 短卡先行，按需展开 | 降低阅读负担，保留比较能力 |
| 展示六类卡、十余张卡同时组合 | 初次只补当前的一步，进阶可展开卡片桌 | 避免将写作变成填满槽位的游戏 |
| 通过弃用率、修改量证明作者性 | 只作观察信号，与作者解释和成品一起看 | 全部接受、少改或自由写都可能是认真选择 |
| 增加独立“去 AI 味 Agent” | 复用语言编辑，按需推敲一处 | 避免多轮同一审美把不同作者磨平 |
| 默认少解释、短句、留白 | 由本场目标和作者偏好决定 | 不将一种文学风格当正确答案 |
| 卡片组合只要 needs/gives 能对上就通过 | 规则校验加可理解的因果预览，保留未知 | 符号匹配不能证明故事成立 |
| 修改大纲就全书自动重写 | 展示影响范围，作者选择重做部分 | 保护已喜欢的场景与个人选择 |

## 11. 优先级：先补体验闭环，再加丰富功能

### P0：已纳入正式首版闭环

1. 三条起步路径与渐进展示；保留直接写作。
2. 短点子卡 + 选中后补一步 + 可选试演。
3. 锁定、局部替换、借用、撤销、旧批次恢复。
4. “只改表达/允许扩写”范围选择，以及基于事实与偏好的推敲。
5. 候选、计划、正文、事实四种状态的正确流转。
6. 新手行为和创作体验测试，与既有系统验收一起执行。

### P1：先做最小配套，再根据验证完善

最小原创示例、反向整理与聚合审阅已作为起步闭环配套纳入 M1/M2；更多题材样例、精细对白试演及更丰富的跨候选提示，根据起步体验证据继续迭代。具体阶段以[正式路线](<../DESIGN.md>) §11 为准。

### P2：有证据再扩展

更大的卡片桌、长期风格偏好学习、独立语音输入、社区反馈等。每项应能说明比现有流程多解决哪个问题，而不是只增加功能数量。

Pi 主通路、双画布、RAG、元素历史和版本管理仍属于原方案首版范围；这里排序的是新增体验工作，不是删除既定能力。

## 12. 验收与研究：不以“通过 AI 检测”为目标

### 12.1 行为契约验收

N01–N14 已迁入[正式产品验收](<../DESIGN.md#L457>)，与 A/K/工作流契约共同维护。覆盖起步、卡片差异、锁定/撤销、迟到结果、修改范围、来源分层、空库、文风选择、批量审阅、视图一致、幂等与偏好作用域。本报告不再重复维护验收表；这些契约尚未运行验证。

### 12.2 新手可用性研究

先用纸面卡片或低保真原型开展小规模形成性研究，例如招募 8–12 位没有小说创作经验的人；人数为研究建议，不是效果保证。

- 任务：把一个点子发展为一场自己愿意继续写的戏；允许任何起步路径。
- 记录：卡在哪里、读了多少、选择与撤销次数、首次可保存片段的时间、是否愿意继续。
- 询问：故事中哪一点是你坚持保留的？如果换另一张卡，会发生什么变化？“没有特别偏好”也是有效回答。
- 区分：理解界面困难、候选本身不好、作者正在思考、模型等待和技术失败。
- 统计：报告完成率、时间分布和访谈差异，不把小样本说成统计显著。
- 编辑量、采用率只作过程线索；不能单独证明作者性或创作质量。测试记录须获得同意，日常使用不默认上传手稿。

### 12.3 中立阅读评价

比较“现有流程”与“卡片/推敲流程”时，尽量保持模型、事实输入、任务、生成预算和长度相近。先评价完整体验；若要知道是哪项设计起作用，再分别消融卡片、试演和推敲，避免把所有收益归因于卡片。

给读者匿名乱序稿件，不标“AI稿/改良稿”。问题包括：

- 能否理解人物为什么行动？有何原文依据？
- 情节衔接、人物说话和具体细节是否服务这场戏？
- 是否想继续读，或用哪稿接着写？
- 是否保留了作者事先选择的目标与约束？

允许“无差别、无法判断、各有优点”。作者、目标读者和编辑的判断分别报告，不折算成一个质量总分；模型评价只作辅助定位。

另外观察不同作者的成品是否越来越像同一种剧情。相似度只能作检索信号，需结合实际行动、结局、关系与细节判断，不能变成“原创率”标签。

## 13. 外部证据与限制

Doshi 与 Hauser 的 [2024 年研究全文](<https://pmc.ncbi.nlm.nih.gov/articles/PMC11244532/>)研究了获得 AI 点子对短故事写作的影响：实验中 AI 点子可以改善部分读者评价，同时作品彼此更相似。这支持同时观察“个人体验/质量”与“作品趋同”，而不是只看生成更快。

该实验主要是非职业参与者用英文写八句话故事，使用当时的 GPT-4 点子；它不能直接证明本平台对中文长篇有效，也不能证明某种卡片数量、写法或“去 AI 味”流程有效。新手也不等于缺乏创造力。

本报告的卡片、微文案和示例为设计构思；其价值仍需通过原型、实际作品与作者反馈验证。
